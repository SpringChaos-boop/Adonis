# Горицвет — сайт персонажа

Статический сайт: шаблон + контент в JSON + сборка в готовый HTML.
Никаких зависимостей и фреймворков — только Node.js для сборки и локального сервера.

## Структура

| Файл | Зачем |
|---|---|
| `content.json` | **Единственный источник контента**: тексты, ссылки, изображения, подписи. |
| `template.html` | Каркас страницы с плейсхолдерами `{{…}}` (шапка, навигация, лайтбокс). |
| `render.js` | Функции рендера контента в HTML. Общие для браузера и сборки. |
| `app.js` | Переключение разделов по hash (`#profile`, `#gallery`), лайтбокс, подстановка данных. |
| `styles.css` | Всё оформление. Палитра — в `:root`. |
| `build.mjs` | Собирает `index.html` (и `sitemap.xml`, если задан `site.url`). |
| `check.mjs` | Проверка контента, ассетов и собранной страницы. |
| `server.mjs` | Локальный сервер без зависимостей. |
| `index.html` | **Результат сборки** — его и публикуют. |
| `404.html`, `robots.txt` | Служебные страницы для хостинга. |
| `assets/` | Изображения, фавикон, обложка для соцсетей. |
| `goritsvet_character_prototype.html` | Исходный макет-прототип. В сборке не участвует, оставлен для истории — можно удалить. |

## Быстрый старт

1. Двойной клик по **`preview.cmd`** — откроется `http://localhost:8080/`.
2. Правите `content.json` → перезагружаете страницу (пересборка не нужна: `app.js` читает JSON на лету).
3. Перед публикацией: `npm run build`, затем `npm run check`.

> Почему сервер, а не двойной клик по `index.html`? `content.json` подгружается через `fetch`, а при `file://` браузер такой запрос блокирует. Если открыть `index.html` напрямую, покажется последняя собранная версия — сайт не сломается, но правки из JSON не подхватятся.

## Как добавить изображение

1. Положите файл в `assets/` (лучше шириной 480/960/1440 px, JPEG качеством ~82).
2. Пропишите в `content.json`, например в `banner`:

```json
"banner": {
  "src": "assets/icarus-960.jpg",
  "srcset": "assets/icarus-480.jpg 480w, assets/icarus-960.jpg 960w",
  "sizes": "(max-width: 700px) 300px, 430px",
  "width": 960,
  "height": 1136,
  "alt": "Описание изображения для незрячих"
}
```

`width`/`height` обязательны — они резервируют место и не дают странице «прыгать» при загрузке.

## Разделы профиля

Секции описаны в `sections` массиве. Номер (`01`, `02`, …) генерируется из порядка — вручную не правится.

- `layout: "half"` — половина ширины;
- `layout: "full"` — на всю ширину;
- `layout: "split"` — текст + изображение (как «Семья»), картинка задаётся в `media`.

## Публикация

Подойдёт любой статический хостинг (GitHub Pages, Netlify, Cloudflare Pages, Vercel).

1. Заполните `site.url` в `content.json` — появятся `canonical`, `og:url` и `sitemap.xml`.
2. `npm run build` и `npm run check`.
3. Загрузите: `index.html`, `styles.css`, `app.js`, `render.js`, `content.json`, `404.html`, `robots.txt`, `assets/` (и `sitemap.xml`).

## Дальше по плану

- **Админ-панель.** Её задача — редактировать `content.json` (а позже строки в Supabase), а не генерировать HTML. Рендер уже отделён (`render.js`), так что UI можно строить поверх той же модели.
- **Supabase.** `app.js` читает данные в одном месте (`loadContent()`), а `render.js` ничего не знает об источнике — замена `fetch('content.json')` на `supabase.from(...)` не затронет разметку.

### Что важно помнить про безопасность админки

- Чтение для всех, запись — только ваш пользователь: RLS-политики (`select using (true)`, `insert/update/delete using (auth.uid() = ...)`).
- `service_role`-ключ нельзя класть в браузер — только сервер/Edge Function.
- Тексты храните как plain text/markdown и экранируйте при выводе (`render.js` уже экранирует всё через `esc()`), а не как готовый HTML.
- Загрузку файлов ограничивайте по типу и размеру, изображения отдавайте уменьшенными (Supabase Storage transformations).
