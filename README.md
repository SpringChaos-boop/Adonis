# Горицвет — сайт персонажа

Статический сайт: контент в JSON, рендер в готовый HTML, публикация без сборки.
**npm, пакеты и фреймворки не нужны.** Node.js — только движок для двух необязательных скриптов (`build.mjs`, `check.mjs`), ничего устанавливать не требуется.

> `package.json` в проекте — не про npm: там одна строка `"type": "module"`, чтобы Node читал `.js`-файлы как ES-модули. Зависимостей и npm-скриптов нет.

## Структура

| Файл | Зачем |
|---|---|
| `content.json` | **Единственный источник контента**: тексты, ссылки, изображения, подписи. |
| `template.html` | Каркас страницы с плейсхолдерами `{{…}}`. |
| `404.template.html` | Каркас страницы 404. |
| `render.js` | Функции рендера контента в HTML. Общие для браузера и сборки. |
| `app.js` | Переключение разделов по hash (`#profile`, `#gallery`), лайтбокс, подстановка данных. |
| `data/provider.js` | Источник контента: Supabase, а при его отсутствии — `content.json`. |
| `data/supabase.js` | Клиент Supabase (Auth, REST, Storage) на чистом `fetch`. |
| `config.js` | **Сюда вписываются `url` и `anonKey` Supabase.** Пусто — сайт читает JSON. |
| `admin.html`, `admin/` | Админ-панель: редактор контента с предпросмотром. |
| `styles.css` | Всё оформление. Палитра — в `:root`. |
| `index.html`, `404.html` | **Результат сборки** — их и публикуют. |
| `build.mjs` / `build.cmd` | Собирает `index.html` и `404.html` (и `sitemap.xml` при заданном `site.url`). |
| `check.mjs` / `check.cmd` | Проверка контента, ассетов и собранных страниц. |
| `server.mjs` / `preview.cmd` | Локальный сервер без зависимостей. |
| `robots.txt`, `.nojekyll` | Служебные файлы для хостинга. |
| `assets/` | Изображения, фавикон, обложка для соцсетей. |
| `supabase/` | `schema.sql` (таблицы, RLS, Storage) и `SETUP.md` — пошаговое подключение. |
| `goritsvet_character_prototype.html` | Исходный макет-прототип. В сборке не участвует — можно удалить. |

## Локальный просмотр

Двойной клик по **`preview.cmd`** → `http://localhost:8080/`.

Правки в `content.json` видны сразу после перезагрузки: `app.js` читает JSON на лету. Пересборка для этого не нужна.

> Почему сервер, а не двойной клик по `index.html`? `content.json` подгружается через `fetch`, а при `file://` браузер такой запрос блокирует. Если открыть `index.html` напрямую, покажется последняя собранная версия — сайт не сломается, но правки из JSON не подхватятся.

## Сборка (необязательно)

- `build.cmd` — обновить `index.html` и `404.html` из `content.json`;
- `check.cmd` — проверить контент, изображения и собранные страницы.

Зачем сборка, если сайт работает и без неё: она «запекает» контент в HTML — это лучше для поисковиков, для превью в соцсетях и для первого кадра до загрузки скриптов. Делать её нужно перед публикацией изменений, если хочется, чтобы статическая версия совпадала с JSON.

## Админ-панель

Открывается по адресу **`admin.html`** — локально `http://localhost:8080/admin.html`, на опубликованном сайте `https://…/admin.html`. Ссылки с публичных страниц на неё нет, `robots.txt` её закрывает, но настоящая защита — Supabase Auth + RLS.

Что внутри: вкладки «Общее», «Персонаж», «Цитата», «Баннер», «Разделы», «Галерея», «Кредиты», живой предпросмотр тем же `render.js`, проверка перед сохранением.

### Режим без Supabase (по умолчанию)

`config.js` пуст → панель работает как редактор:

1. Правки автоматически сохраняются как **черновик в браузере** (кнопка «Забыть черновик» сбрасывает).
2. **Сохранить черновик** — зафиксировать и снять признак «не сохранено».
3. **Скачать content.json** — файл кладётся в папку сайта вместо старого, затем коммит и `build.cmd`.
4. **Загрузить файл…** — открыть существующий `content.json` в редакторе.

Картинки в этом режиме подготавливаются (обрезаются до 1600 px, пережимаются в WebP/PNG) и **скачиваются** готовым файлом: положите его в `assets/` — путь уже прописан в поле.

### Режим Supabase

Заполните `config.js` (см. ниже) → войдите в админке → правки сохраняются кнопкой **Сохранить на сайт** и появляются на сайте сразу, без пересборки. Изображения уходят в Storage и подставляются публичными URL.

## Supabase

Пошаговая инструкция — [supabase/SETUP.md](supabase/SETUP.md), SQL — [supabase/schema.sql](supabase/schema.sql). Коротко:

1. Создать проект Supabase.
2. Выполнить `schema.sql` в SQL Editor (таблицы, RLS, bucket `media`).
3. Создать пользователя в Authentication → Users и выключить регистрацию.
4. Вписать `url` и `anonKey` в `config.js`.
5. Войти в `admin.html` и нажать «Сохранить на сайт».

`anon`-ключ публичен по замыслу, `service_role` в браузер не попадает. Пока `config.js` пуст или проект недоступен, сайт молча работает на `content.json`.

## Публикация через GitHub Desktop

GitHub Desktop уже установлен на этом компьютере. Вся публикация — через его окно, терминал не нужен. Ветка репозитория уже переименована в `main`.

### Первая публикация

1. **Добавьте папку.** `File` → `Add local repository…` → укажите папку сайта (`…\Desktop\сайт профиль горицвет`) → `Add`.
   Папка уже git-репозиторий с историей из трёх коммитов, поэтому `Create new repository` выбирать не нужно.
   Если приложение не авторизовано: `File` → `Options` → `Accounts` → `Sign in` → GitHub.com.

2. **Опубликуйте репозиторий.** Кнопка **`Publish repository`** справа сверху. Имя — например `goritsvet`.
   Снимите галочку **`Keep this code private`**: на бесплатном тарифе GitHub Pages работает только с публичными репозиториями. Нажмите `Publish repository`.

3. **Включите Pages.** На github.com откройте репозиторий → **Settings** → **Pages** → *Build and deployment*: Source — **Deploy from a branch**, Branch — **main**, папка — **/ (root)** → **Save**.
   Через 1–2 минуты там же появится адрес вида `https://ЛОГИН.github.io/goritsvet/`.

4. **Пропишите адрес сайта.** В `content.json` заполните `"url": "https://ЛОГИН.github.io/goritsvet/"` (ровно со слэшем на конце) и запустите `build.cmd`.
   В GitHub Desktop появятся изменения: в поле Summary введите `адрес сайта` → **`Commit to main`** → **`Push origin`**.
   `content.json` сохраняйте в UTF-8 (VS Code — по умолчанию; в Блокноте явно выберите UTF-8), иначе кириллица превратится в «кракозябры».

5. **Проверьте сайт:** открывается главная, работает вкладка «Галерея», грузится картина, а несуществующий адрес показывает страницу 404.

### Как обновлять контент

Правите `content.json` и файлы в `assets/` → в GitHub Desktop появились изменения → Summary → **`Commit to main`** → **`Push origin`**.

Сайт подхватит изменения сразу (JS читает JSON), но «запечённая» версия в `index.html` обновится только после `build.cmd`. Для правок текста сборка не обязательна, для новых изображений и смены `site.url` — желательна.

### Если что-то не так

| Симптом | Что делать |
|---|---|
| Открывается 404 GitHub | Pages ещё собирались или в настройках указана не та ветка/папка: проверьте `main` и `/ (root)`. |
| Сайт открылся, но контент старый | Кэш браузера: `Ctrl+F5`. |
| Вместо заголовков видно `{{site.title}}` | Пропал файл `.nojekyll` — верните его и запушьте снова. |
| Не грузятся картинки | В коммит не попала папка `assets/`: перед коммитом проверьте список файлов в GitHub Desktop. |
| Кириллица «кракозябрами» | `content.json` сохранён не в UTF-8 — пересохраните и запушьте. |
| Нужен адрес пользовательского сайта | Репозиторий `ЛОГИН.github.io` публикуется в корне домена, тогда `site.url` = `https://ЛОГИН.github.io/`. |

### Через терминал (если удобнее)

```
git remote add origin https://github.com/ЛОГИН/goritsvet.git
git push -u origin main
```

### Особенности адреса

- Сайт-проект живёт в подкаталоге `/ИМЯ-РЕПОЗИТОРИЯ/`. Все пути внутри сайта относительные (`assets/…`, `styles.css`), поэтому подкаталог ничего не ломает.
- Пользовательский сайт `ЛОГИН.github.io` (репозиторий с таким именем) публикуется в корне домена — тогда `site.url` = `https://ЛОГИН.github.io/`.

## Как добавить изображение

1. Положите файл в `assets/` (лучше шириной 480/960/1440 px, JPEG качеством ~82).
2. Пропишите в `content.json`, например в `banner`:

```json
"banner": {
  "src": "assets/icarus-960.jpg",
  "srcset": "assets/icarus-480.jpg 480w, assets/icarus-960.jpg 960w",
  "sizes": "(max-width: 700px) 300px, 430px",
  "width": 960,
  "height": 1136,
  "alt": "Описание изображения для незрячих"
}
```

`width`/`height` обязательны — они резервируют место и не дают странице «прыгать» при загрузке.

## Разделы профиля

Секции описаны в массиве `sections`. Номер (`01`, `02`, …) генерируется из порядка — вручную не правится.

- `layout: "half"` — половина ширины;
- `layout: "full"` — на всю ширину;
- `layout: "split"` — текст + изображение (как «Семья»), картинка задаётся в `media`.

## Дальше по плану

- **Админ-панель.** Её задача — редактировать `content.json` (позже — строки в Supabase), а не генерировать HTML. Рендер уже отделён (`render.js`), так что UI строится поверх той же модели.
- **Supabase.** `app.js` читает данные в одном месте (`loadContent()`), а `render.js` ничего не знает об источнике — замена `fetch('content.json')` на `supabase.from(...)` не затронет разметку.

### Что важно помнить про безопасность админки

- Чтение для всех, запись — только ваш пользователь: RLS-политики (`select using (true)`, `insert/update/delete using (auth.uid() = ...)`).
- `service_role`-ключ нельзя класть в браузер — только сервер/Edge Function.
- Тексты храните как plain text/markdown и экранируйте при выводе (`render.js` уже экранирует всё через `esc()`), а не как готовый HTML.
- Загрузку файлов ограничивайте по типу и размеру, изображения отдавайте уменьшенными (Supabase Storage transformations).
