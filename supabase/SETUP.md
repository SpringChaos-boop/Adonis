# Подключение Supabase

Пошагово, без терминала. Занимает ~15 минут. Проект на бесплатном тарифе подходит.

## 1. Создать проект

1. [supabase.com](https://supabase.com) → `Sign in` → `New project`.
2. Имя: `goritsvet`. Пароль базы данных — сгенерируйте и **сохраните** (он понадобится только для прямого доступа к базе, сайту не нужен).
3. Регион — ближайший к аудитории (например, `eu-central`).
4. Дождитесь, пока проект закончит инициализацию (~2 минуты).

## 2. Применить схему

1. В левом меню → **SQL Editor** → `New query`.
2. Скопируйте целиком `supabase/schema.sql` и нажмите **Run**.
3. Должно появиться `Success. No rows returned`. Скрипт можно запускать повторно.

Что он создаст:

| Объект | Зачем |
|---|---|
| `site_content` | одна строка с JSON контента (`id = 'goritsvet'`) |
| `content_history` | снимок предыдущей версии при каждом сохранении |
| RLS-политики | `select` — всем, `insert/update` — только авторизованным |
| bucket `media` | публичные изображения до 10 МБ |

## 3. Создать пользователя-владельца

1. **Authentication** → **Users** → `Add user` → `Create new user`.
2. Введите e-mail и пароль, включите **Auto Confirm User** (иначе вход не пустит).
3. Сохраните пароль — это единственный аккаунт для админки.

> Затем закройте регистрацию: **Authentication** → **Sign In / Providers** → Email → выключите **Allow new users to sign up**. Иначе кто угодно сможет завести аккаунт. Писать в контент он всё равно не сможет (политики `to authenticated`… но лучше не проверять).

## 4. Вписать ключи в `config.js`

1. **Project Settings** → **API** (в новых версиях — **Data API** / **API Keys**).
2. Скопируйте:
   - **Project URL** → `url`
   - **anon public** — ключ → `anonKey`
3. Отредактируйте `config.js`:

```js
export const supabaseConfig = {
  url: 'https://abcdefghijkl.supabase.co',
  anonKey: 'eyJhbGciOi...',
};
```

`anon`-ключ **публичный по замыслу**: он лежит в браузере у всех посетителей. Запись закрывают RLS-политики, а не секретность ключа. `service_role` в браузере — категорически нельзя.

## 5. Первый вход и сохранение

1. Откройте `admin.html` (локально через `preview.cmd` или на опубликованном сайте).
2. Справа сверху → **Войти** → e-mail и пароль из шага 3.
3. Отредактируйте что-нибудь → **Сохранить на сайт**.
4. Обновите публичную страницу — изменения на месте.

Изображения при сохранении уходят в bucket `media` и подставляются абсолютными URL.

## 6. Как это работает

```
config.js → data/provider.js ──► Supabase (site_content)
                            └──► content.json (если Supabase пуст/недоступен)
```

- Сайт читает контент из Supabase и **не требует пересборки**: `app.js` подтягивает данные в браузере.
- `content.json` остаётся запасным вариантом: если проект Supabase на паузе или ключи неверны, сайт покажет его. Поэтому после крупных правок полезно нажать в админке **Скачать content.json**, положить файл в папку и закоммитить — это же обновляет предзагруженную версию (`build.cmd`).
- Админка при сохранении делает upsert строки `id = 'goritsvet'`; история версий пишется триггером.

## Если что-то не так

| Симптом | Причина |
|---|---|
| «Supabase не настроен» | Пустые `url`/`anonKey` в `config.js` или файл не сохранён |
| «Нужно войти» | Сессия истекла — нажмите **Выйти** и войдите снова |
| `401` при сохранении | Пользователь не создан или не подтверждён (Auto Confirm) |
| `42501` / «row-level security» | Не применён `schema.sql` либо политики не создались |
| Ошибка загрузки картинки | Не создан bucket `media` или не применены политики Storage |
| Сайт показывает старый контент | Кэш браузера (`Ctrl+F5`) или строка ещё не создана |
| Проект «на паузе» | Бесплатный тариф усыпляет проект после недели без запросов; разбудите в панели Supabase. Сайт в это время работает на `content.json` |

## Откат к локальному режиму

Очистите `url` и `anonKey` в `config.js` — сайт снова читает `content.json`, админка работает с черновиком и скачиванием файла. Данные в Supabase при этом не удаляются.
